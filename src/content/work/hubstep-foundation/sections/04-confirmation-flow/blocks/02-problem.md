### Problem

As sales requests and spec changes piled up, the existing table UI made it increasingly hard to tell which list had a problem, and what needed fixing before it could go to print.

In particular, a state that could still go to print with caution and a state that couldn't go to print until resolved were mixed together on the same screen, so the meaning of an alert, and what needed to happen before confirming, were both hard to read.

Looking back through the internal feedback log, I found **14 items** directly related to the address-label design and its confirmation flow.

**Feedback we received directly**

> The "※Alert not yet resolved" message is too unclear. If it's an error state, please show a clearer alert.

> We'd like an alert before the address-label design is confirmed, and to be able to tell that it can't be changed once confirmed.
